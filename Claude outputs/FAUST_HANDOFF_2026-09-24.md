# Фауст (бывший Jarvis) — передача проекта новому агенту

Вставь этот файл первым сообщением в новую сессию Claude Code, открытую в `C:\diplom`.

## Как со мной работать

- Общайся по-русски. Код пиши с **подробными комментариями на русском**: автор учится и хочет понимать каждую часть.
- Двигайся маленькими проверяемыми шагами. **Сначала измерь или воспроизведи, потом утверждай.** В прошлой сессии замеры несколько раз опровергали очевидные гипотезы: нагрузку окон, «одинаковые кадры», причину промахов агента.
- **Не делай навязчивых действий без спроса.** Не открывай Chrome на моём экране для тестов, не запускай ИИ-задачи, которые откроют мои личные чаты. Файлы в `%USERPROFILE%\.jarvis-agent\` (токен, логи, журналы) читай только по необходимости и точечно (grep), содержимое токена — никогда.
- Не ломай работающее перед защитой диплома. Если что-то не проверено — прямо так и скажи.

## Что за проект

Дипломная работа (бакалавриат), тема «AI-агент для автоматизации многоэтапных пользовательских задач». Управление ПК с телефона естественным языком: LLM (Gemini) и computer-use агент.

```
Телефон (Kotlin/Compose) <--WS--> Релей (Spring Boot, Docker + Postgres) <--WS--> Агент на ПК (Java 21, Robot, Selenium)
```

| Папка | Что внутри |
|---|---|
| `C:\diplom\jarvis` | KMP: `:shared` (протокол), `:androidApp` (приложение Faust) |
| `C:\diplom\jarvis-relay` | релей, `docker-compose.yml` (relay + postgres), `.env` |
| `C:\diplom\jarvis-agent` | агент на ПК |
| `C:\diplom\faust.ps1` + `start-faust.bat` | **лёгкий запуск** (см. ниже) |
| `C:\diplom\Claude outputs\` | передаточные документы |

**Инварианты (не ломать):**
1. Протокол меняется синхронно в трёх местах: Kotlin `:shared`, Java-зеркало в релее, Java-зеркало в агенте.
2. Whitelist команд на релее — граница безопасности; shutdown/reboot вне списка.
3. Ключ LLM только на релее (`.env`), не в APK и не в агенте.
4. Агент сам звонит на релей (NAT).
5. Токен и deviceId переживают перезапуск.

## Как запускать

Двойной щелчок по `C:\diplom\start-faust.bat` → меню:

| Пункт | Что делает |
|---|---|
| 1 | Запустить: Docker, релей, агент |
| 2 | QR для телефона |
| 3 | Демо анимаций |
| 4 | Демо для записи экрана |
| 5 | Поставить приложение на телефон |
| 6 | Состояние |
| 7 | Остановить |

Из консоли то же: `start-faust.bat start|qr|demo|record|phone|status|stop`.

- Скрипт включает на релее открытую регистрацию (`JARVIS_OPEN_REGISTRATION=true`), поэтому кода для ПК нет. Путь новичка: «Подключить» → «Привязать телефон» → QR.
- Агент запускается через `javaw` из готовой сборки `jarvis-agent\build\install\...\lib`, без Gradle. Пересборка — только если исходники новее jar. Если запущенный агент старше сборки, скрипт его перезапускает.
- Релей пересобирается, только если **точно** известно, что его код менялся; скрипт пишет, какой файл это вызвал.
- Повторный запуск, когда всё уже работает, занимает ~2 с.
- Java 21 есть только в `%USERPROFILE%\.gradle\jdks\eclipse_adoptium-21-amd64-windows.2`; `JAVA_HOME` указывает на 17. Все `JavaExec`-задачи в `build.gradle.kts` агента привязаны к toolchain 21.
- Лог агента: `%USERPROFILE%\.jarvis-agent\agent.log`. Журналы ИИ-задач: `...\runs\*.jsonl` (цель, режим, трейс с координатами).
- `faust.ps1` должен быть в **UTF-8 с BOM**, иначе Windows PowerShell 5.1 ломает кириллицу. После правок проверяй BOM и синтаксис через `[System.Management.Automation.Language.Parser]::ParseFile`.

## Что сделано в прошлой сессии (кратко)

**Телефон**
- Свои быстрые команды-чипы (`CustomActions.kt`, `CustomActionsScreen.kt`).
- Навигация через выдвижное меню и Material-иконки: раньше 7 эмодзи-кнопок не влезали в шапку.
- Анимации переходов; декодирование кадров вне главного потока (`FrameDecoding.kt`).

**Агент**
- `open_app` открывает всё, что есть в «Пуске» (`AppCatalog`: `Get-StartApps` + транслит + Левенштейн).
- Кэш траекторий (`TrajectoryCache`): повтор выученной задачи без LLM, с параметризацией слота.
- Адаптивный `settle()` в `BrowserAgent`: ~280 мс вместо 1500 мс на шаг.
- Стрим экрана не шлёт побайтово одинаковые кадры.

**Анимации «Фауст»** (спецификация — `FAUST_OVERLAY_PROMPTS.md`, у пользователя):
- A — заставка; B — рамка и плашка; C — виджет; D — ореол у курсора и всплески.
- Общая база: `WinOverlayUtil` (JNA: click-through, `WDA_EXCLUDEFROMCAPTURE`), `FaustLogoPainter`, `Easing`, `AgentOverlays` (запасной путь: на время снимка или клика прячет окна, которые Windows не смогла исключить).
- `FaustOverlayController` — три режима:
  - обычная команда → карточка на 2.5 с;
  - «Экран ПК» → рамка + ореол; «Остановить» блокирует тапы с телефона до повторного открытия;
  - ИИ-задача → всё вместе плюс курсор-призрак в браузере.
- Демо: `FaustOverlayDemo`.

**Пиксельный агент (SCREEN)**
- Новые действия `open_app` (через общий `CommandExecutor.launchApp`) и `key` (Alt+F4 и Win запрещены).
- Промпт запрещает клики по панели задач.
- Пометка «повтор» против хождения по кругу.
- Причина промахов с Telegram, по журналам: модель кликала по значку на панели задач, разброс ±40 px, попадала в соседний WhatsApp.

## Не проверено / известные проблемы

- **Курсор-призрак в браузере.** Формула «CSS-координаты → экран» (`BrowserAgent.elementOnScreen`) не проверена на настоящем Chrome: пользователь отменил тест. Проверь на реальной ИИ-задаче в браузере и спроси пользователя, садится ли призрак на кнопку.
- **Новые действия пиксельного агента** проверены без модели. Выберет ли Gemini `open_app` — не проверено на живой задаче.
- **Нагрузка:**

  | Оверлей | CPU |
  |---|---|
  | рамка B, 10 к/с (`overlay.frameFps`) | ~8–12% ядра |
  | виджет C | ~13% |
  | заставка A | 21–38%, первые 4.7 с |

  Причина — дорогое обновление прозрачного окна в Java.
- **`WDA_EXCLUDEFROMCAPTURE`** прячет оверлеи и от OBS, Zoom и «Ножниц». Для записи демо: `overlay.excludeFromCapture=false` или пункт меню 4.
- **Из чек-листа ещё не сделано:**
  - `stepsTaken` = `trace.size()`, а не число шагов — **испортит таблицы диплома**;
  - `kill_process` по подстроке;
  - порт 5432 опубликован наружу;
  - нет R8 в `androidApp`;
  - в агенте нет тестов;
  - `ОБЪЯСНЕНИЕ-ПРОЕКТА.md` отстал: пишет, что `agent_task` блокирует WebSocket, это уже не так;
  - кэш «фраза → команда» на релее;
  - `setVolume` компилирует C# на каждый вызов.
- Метрики, датасет и научную часть пользователь делает позже.

# Следующие задачи

## Задача 1 (главная). «DOM» для обычных программ через Windows UI Automation

**Зачем.** В пиксельном режиме (`ScreenAgent`) модель получает картинку и целится «на глаз». Каждый шаг занимает **5–38 секунд** (модель разбирает изображение), и клики промахиваются. В браузере эту проблему давно решает DOM-режим (`BrowserAgent`): модель получает короткий список элементов `[5] <button> "Поиск"` и отвечает номером, а клик попадает точно. Нужно то же для обычных программ — Telegram, Проводник, Настройки, Блокнот. Windows отдаёт дерево элементов окна через **UI Automation (UIA)**: имя, тип элемента, прямоугольник, доступные действия.

**Порядок работы:**

1. **Сначала разведка, код потом.** Выгрузи дерево UIA переднего окна для 3–4 программ: Telegram Desktop, Проводник, Параметры Windows, Блокнот. Проверь, что оно реально полезно. Telegram Desktop написан на Qt, и Qt отдаёт UIA **не полностью** — дерево может оказаться почти пустым. Самый быстрый способ разведки — PowerShell с `UIAutomationClient` / `System.Windows.Automation`. Покажи пользователю, что нашлось, **до** того, как строить механизм.
2. **Выбор способа доступа из Java** — сравни и объясни пользователю:
   - (а) JNA + COM `IUIAutomation` прямо из Java — без внешних процессов, но много ручного COM-кода;
   - (б) маленький помощник на C#/.NET (exe), который отдаёт JSON с элементами окна, — просто и быстро, но ещё один бинарник в сборке;
   - (в) PowerShell на каждый снимок — самое простое, но ~0.5–1 с на вызов.

   Замерь время снимка дерева для каждого варианта.
3. **Новый режим агента** (например, `UiaAgent` или гибрид внутри `ScreenAgent`):
   - снимок — список видимых элементов переднего окна `[i] <ControlType> "Name"` с центрами прямоугольников, как `PageElement` в DOM-режиме;
   - модель отвечает номером элемента;
   - клик — по центру прямоугольника (через `AgentOverlays.mouseAction` и `FaustOverlayController.onClick`, как сейчас) или через `InvokePattern`;
   - ввод — через `ValuePattern` или вставку.
4. **Гибрид и откат.** Если дерево пустое или бедное (Qt, игры), агент возвращается к пиксельному режиму. Оставь и `open_app`, и `key`, и пометку «повтор».
5. **Безопасность.** Сохрани `SensitiveInputGuard`: поля паролей в UIA помечаются `IsPassword` — используй это как ещё один рубеж.
6. **Измерь до и после** на фиксированном наборе задач («открой Telegram, чат с X», «в Проводнике открой Загрузки», «в Блокноте напиши …»): число шагов, время, успех. Это готовая таблица для научной части диплома.

Изменения только в `jarvis-agent`. Протокол не трогать: `scope=SCREEN` остаётся, режим выбирается внутри агента.

## Задача 2. Релей сам разделяет «открыть программу» и «задачу внутри неё»

**Зачем.** Фраза «зайди в Telegram в чат с Лерой» сейчас целиком уходит модели как `agent_task`, и уже модель решает, как открыть Telegram. Надёжнее, если программа откроется **детерминированно, без модели**, а модель получит только задачу внутри уже открытого окна.

**Как:**
- **Вариант без смены протокола.** Промпт `GeminiIntentParser` на релее учится возвращать для таких фраз поле программы, а релей шлёт агенту две команды подряд: `open_app("Telegram")`, затем `agent_task("открой чат с Лерой", scope=screen)`. Минус: у телефона один requestId, нужно продумать, как показать оба ответа.
- **Вариант чище.** Необязательное поле `app` в `AgentTask`. Агент перед циклом вызывает `CommandExecutor.launchApp(app)`, ждёт окно и запускает цикл уже внутри программы. Это **смена протокола в трёх местах** (Kotlin `:shared`, Java в релее, Java в агенте). Поле необязательное — старые клиенты не ломаются. Добавь round-trip тест в `shared/src/commonTest` и тест парсера в релее (там уже есть `GeminiIntentParserTest`).
- Посоветуйся с пользователем, какой вариант выбрать. Объясни компромисс.
- Измерь на тех же фразах: сколько шагов и секунд уходило раньше и сейчас.

## Другие идеи, как сделать агента точнее и умнее (на будущее)

- **Set-of-Marks для пиксельного режима.** Если UIA-дерева нет, нарисовать на снимке пронумерованные рамки вокруг найденных элементов (через UIA или простой детектор) и просить номер вместо координат.
- **Снимок только активного окна** вместо всего экрана: больше деталей, нет соблазна кликнуть в панель задач.
- **Приближение в два шага:** модель выбирает область, получает увеличенный кусок и уточняет точку.
- **Проверка результата после повтора из памяти** (`TrajectoryCache`): один вопрос модели «цель достигнута?».
- **Кэш траекторий для режима UIA**, когда он появится: по именам элементов траектории переносимы лучше, чем по пикселям.
