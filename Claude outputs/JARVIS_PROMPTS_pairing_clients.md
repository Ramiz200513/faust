# Промпты: подключить клиентов к пPairРёРЅРіу релея (агент + приложение)

Контекст: релей (jarvis-relay) теперь авторизует по паринг-коду. Первое Auth-сообщение
устройства должно содержать в поле `token` ОДНОРАЗОВЫЙ КОД. Релей гасит код, создаёт
устройство и ОДИН РАЗ возвращает ПОСТОЯННЫЙ ТОКЕН в поле `reason` ответа AuthResult
(ok=true). Дальше устройство обязано слать этот постоянный токен.
Сейчас агент и приложение шлют старый общий токен и получают "invalid pairing code".
Формат сообщений НЕ менять — меняется только логика клиента.

================================================================
## 1. АГЕНТ (jarvis-agent) — сохранять и переиспользовать постоянный токен
================================================================
Проект jarvis-agent (Java 21), файл RelayClient.java (+ AgentMain по необходимости).

Задача:
1) Хранение токена: файл рядом с агентом, напр. token.properties в рабочей папке
   (или $HOME/.jarvis-agent/token). Прочитать при старте, записать при получении.
2) Логика Auth при подключении (в onOpen):
   - если сохранённый постоянный токен ЕСТЬ — слать его в поле token;
   - если НЕТ — слать одноразовый код привязки, переданный аргументом запуска
     (AgentMain args: [0] url, [1] pairing-code); это первый запуск.
3) Обработка AuthResult:
   - ok=true и reason не пустой -> это ПОСТОЯННЫЙ ТОКЕН: сохранить в файл и
     использовать дальше (в т.ч. при реконнекте);
   - ok=true и reason пустой -> уже авторизованы постоянным токеном, всё ок;
   - ok=false -> НЕ долбить реконнектом бесконечно: залогировать понятно
     ("паринг не прошёл: <reason>") и остановить попытки (или увеличить паузу до
     минуты), чтобы не спамить сервер.
4) Реконнект должен использовать УЖЕ СОХРАНЁННЫЙ постоянный токен, а не код.

Готово, когда: первый запуск `run --args="ws://... <код>"` привязывает агент и
сохраняет постоянный токен; последующие запуски `run --args="ws://..."` (без кода)
подключаются по сохранённому токену; при неверном коде агент не уходит в вечный цикл.

Инварианты: формат JSON-сообщений не менять; постоянный токен не логировать открыто.
Объясняй код по-русски.

================================================================
## 2. ПРИЛОЖЕНИЕ (jarvis / androidApp) — экран привязки по коду + хранение токена
================================================================
Проект jarvis, модуль androidApp (Kotlin, Compose). Сейчас в UI зашит общий токен.

Задача:
1) Хранение через DataStore: постоянный токен устройства (и адрес релея).
2) Если токена ещё нет — показать экран/диалог "Привязка": поле ввода кода
   (позже — скан QR), кнопка "Привязать".
3) При привязке: подключиться к релею и в первом Auth прислать введённый код как token.
   В обработке AuthResult: если ok=true и reason не пуст — сохранить reason как
   постоянный токен в DataStore, дальше показывать экран чата.
4) Если токен уже сохранён — сразу подключаться им, без экрана привязки.
5) ok=false -> показать сообщение "код неверный или истёк", остаться на экране привязки.

Готово, когда: с полученным кодом (curl из README) приложение привязывается, сохраняет
постоянный токен и после перезапуска подключается без ввода кода.

Инварианты: протокол не менять сверх необходимого; JarvisClient не ломать (логику
Auth/сохранения обернуть вокруг него); ошибки без краша.
Объясняй код по-русски.
