# «Фауст»: что реализовано, стек технологий, дальнейшие действия

Тема: AI-агент для автоматизации многоэтапных пользовательских задач.
Состояние на 13 октября 2026 года.

## 1. Коротко о системе

Пользователь говорит или пишет команду в телефон, и компьютер её выполняет. Система состоит из трёх программ:

- **приложение на телефоне** — принимает команду, показывает ход выполнения и результат;
- **релей (сервер)** — проверяет, кто обращается, превращает фразу в точную команду, не пропускает опасное, ведёт журнал;
- **агент на компьютере** — реально двигает мышь, печатает, открывает программы.

Простые команды (громкость, открыть программу, скриншот) выполняются сразу. Сложные выполняет ИИ-агент: смотрит на экран, выбирает действие, выполняет его и повторяет, пока цель не достигнута.

## 2. Что реализовано по замечаниям руководителей

### 2.1. Многоэтапные задачи через несколько программ

Замечание: демонстрация выглядела как набор одиночных команд; нужны настоящие многоэтапные задачи, например «скачай файл в браузере и отправь его людям в мессенджере».

Сделано:

- **Планировщик.** Большая просьба разбивается на подзадачи, каждая — в одной программе: «скачать архив в браузере», «открыть Telegram», «отправить файл в чат».
- **Передача результата между шагами.** Что именно скачалось и куда, определяет программа, а не модель; точный путь к файлу получает следующий шаг.
- **Проверка каждого шага.** Появился ли файл — проверяет код. Видно ли сообщение в чате — проверяет отдельный запрос к модели, независимый от исполнителя.
- **Перестройка плана.** Если шаг не удался, планировщик получает причину и строит новое продолжение (не больше двух раз).
- **План виден человеку** — чек-листом на телефоне и панелью на экране компьютера.
- **Работа с файлами без «угадывания»:** найти файл по части имени, прикрепить его в программе через буфер обмена, распаковать архив.

Измерено на рабочем ноутбуке (30 сентября — 1 октября):

| Сценарий | С планировщиком | Без планировщика |
|---|---|---|
| Создать папку и скопировать файл (одна программа) | выполнено, 10 шагов, 52 с | выполнено, 14 шагов, 87 с |
| Курс валюты с сайта → Блокнот → сохранить файл | выполнено, 13 шагов, 99 с | не выполнено |
| Скачать архив → отправить в Telegram | выполнено, 6 шагов, 36 с | не выполнено |
| Скачать архив → распаковать → отправить файл из него | выполнено, 9 шагов, 56 с | не запускался |
| Та же отправка во второй раз (из памяти) | 18 с, без обращений к модели | — |

Вывод: в одной программе план не обязателен, а задачи через несколько программ без него не выполняются.

### 2.2. ИИ сам спрашивает человека

Замечание: агент не должен молча сдаваться или угадывать; он должен уточнять, что делать, какой файл, кому.

Сделано:

- Агент задаёт вопрос на телефон карточкой с кнопками-вариантами; ответить можно кнопкой, текстом или голосом.
- Спрашивает в трёх случаях: не хватает данных; подходящих вариантов несколько (два контакта с одним именем); перед необратимым действием — отправить, удалить.
- Правила заданы программой, а не доверены модели: не больше пяти вопросов на задачу, один и тот же вопрос дважды не задаётся, ответ помнится до конца задачи, молчание считается отказом.
- Согласие на необратимое действие засчитывает программа: «да» — только однозначное. Ответ «да, но только Лере» считается уточнением, и план составляется заново.
- Вопросы про пароли, коды из SMS и данные карт на телефон не отправляются.

Проверка формулировок без управления экраном: модель спросила или промолчала там, где ожидалось, в 18 случаях из 18.

### 2.3. Собственная модель, а не только готовый сервис

Замечание: что в работе сделано самостоятельно, а не взято у Google Gemini.

Сделано:

- Фразу пользователя первой разбирает **собственная дообученная модель** — открытая Qwen2.5 (0,5 млрд параметров), дообученная методом LoRA на собственном наборе из 17 тысяч примеров. Работает на том же компьютере, без интернета.
- Gemini подключается, только если своя модель не уверена, и служит «учителем»: придумывает и размечает живые фразы для обучения.
- Подготовлены два экзамена, на которых модель не обучалась: 250 фраз, размеченных автором, и 201 фраза, придуманная и размеченная Gemini.

| | Правила без моделей | Gemini | Своя модель | Связка «своя модель, при сомнении Gemini» |
|---|---|---|---|---|
| Экзамен из 250 фраз | 39,6% | 100% | 97,2% | 100% |
| Экзамен из 201 живой фразы | — | эталон | 89,1% | 96,5% (расчёт) |
| Задержка, медиана | 0 мс | 2013 мс | 133 мс | 140 мс |

Связка даёт ту же точность, что Gemini, и отвечает примерно в 14 раз быстрее: 82% фраз своя модель разбирает сама.

### 2.4. Что добавлено сверх замечаний

- **Навыки** — три способа научить агента составной рутине: рецепт словами на телефоне, доверенный скрипт пользователя, показ действий мышью.
- **Память.** Успешно решённая задача и её план запоминаются и повторяются без обращения к модели.
- **Наглядность.** «Рентген» — рамки и номера элементов окна, как их видит модель; панель «План и мысли».
- **Безопасность, найденная замерами.** Запрет опасных целей для агента (выключение компьютера, форматирование, переводы денег, покупки) и запрет терминалов. Обе дыры обнаружены на живых прогонах и закрыты программными проверками.
- **Тесты.** 109 автоматических тестов агента и 25 тестов релея.

## 3. Стек технологий

| Часть | Технологии |
|---|---|
| Приложение на телефоне | Kotlin 2.1, Jetpack Compose (Material 3), OkHttp (WebSocket), kotlinx.serialization, корутины, DataStore, Vosk (офлайн-распознавание слова «Фауст»), ZXing (QR-код) |
| Релей | Java 21, Spring Boot 3.3 (Web, WebSocket, Data JPA), PostgreSQL 16, BCrypt, Docker и docker compose |
| Агент на компьютере | Java 21, `java.awt.Robot`, Selenium 4 (Chrome), Windows UI Automation через помощник на C# (.NET 9), JNA, Swing, Jackson, JUnit 5 |
| Собственная модель | Python 3.11, PyTorch, LoRA (дообучение Qwen2.5-0.5B-Instruct), llama.cpp (формат GGUF), Ollama (запуск модели) |
| Внешняя модель | Google Gemini — «зрение» агента, планирование, запасной разбор фраз; ключ хранится только на релее |
| Протокол | JSON поверх WebSocket; описан на Kotlin и продублирован на Java в релее и агенте |
| Сборка и запуск | Gradle, PowerShell-скрипт запуска всей системы |

Обучение модели выполнено на ноутбуке с видеокартой RTX 3050 Ti (4 ГБ): 65 минут на вторую версию.

## 4. Ограничения на сегодня

- Цифры многоэтапных сценариев получены по одному прогону; модель не детерминирована, нужны повторы.
- Своя модель сама по себе слабее Gemini (89,1% согласия на живых фразах); вровень идёт только связка.
- Экзамен из фраз реального пользователя ещё не собран; второй экзамен размечала модель, человек разметку не перепроверял.
- Самообучение на «уроках» написано и покрыто тестами, но вживую не прогонялось.
- Обучение показом вживую до конца не проверено; голосовой ответ на вопрос не проверен на телефоне.
- Агент работает только в Windows; соединение не шифруется (нужен TLS или защищённый туннель).

## 5. Дальнейшие действия

1. **Замеры.** Набор сценариев с повторами (5–10 на сценарий): доля успеха, время, число шагов, число обращений к модели, стоимость задачи.
2. **Скорость и надёжность шага.** Горячие клавиши вместо кликов, готовые последовательности для частых программ (мессенджер, проводник, браузер), несколько действий за одно обращение к модели.
3. **Длинные связки.** «Для каждого из списка», ожидание события, продолжение с места сбоя. Рассылка — только по заданному списку получателей, с подтверждением и ограничением числа.
4. **Инструменты разработчика.** Узкие команды git (status, commit, push, pull) для разрешённых папок с подтверждением; работа в Android Studio через горячие клавиши.
5. **Понимание фраз.** Составные фразы из нескольких команд, новые быстрые команды (пауза, относительная громкость), ещё один сбор живых фраз для обучения, экзамен из фраз пользователя.
6. **Проверка вживую** того, что пока проверено только тестами: самообучение, обучение показом, голосовой диалог.
7. **Подготовка к защите.** Заморозка версии, сценарий демонстрации, возврат подтверждений на компьютере, научная часть с таблицами замеров.
