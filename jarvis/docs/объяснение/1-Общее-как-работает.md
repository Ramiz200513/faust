## 1. Что это за проект одной фразой

Ты говоришь или пишешь в телефон: **«Фауст, сделай потише»** или **«скачай архив с сайта и отправь его мне в Telegram»** — и компьютер дома это делает. Простые вещи (громкость, открыть программу, скриншот) выполняются сразу. Сложные многошаговые выполняет **ИИ-агент**: он сам смотрит на экран, решает, куда нажать, нажимает и так шаг за шагом, пока не выполнит цель. Задачу через несколько программ он сначала **разбивает на план**, а если чего-то не знает («какой файл? кому?») — **спрашивает тебя на телефоне**, а не угадывает и не сдаётся.

В интерфейсе проект называется **Faust / Фауст** (это имя и слово-триггер), в коде и папках — **Jarvis**. Это одно и то же.

## 2. Аналогия, которая объясняет всю архитектуру

Представь, что ты управляешь роботом-уборщиком в квартире, находясь на работе.

| В жизни | В проекте | Что делает |
|---|---|---|
| Пульт в руке | **Телефон** (Android-приложение) | Принимает твою команду, показывает результат |
| Диспетчерская служба | **Релей** (сервер) | Проверяет, кто звонит, переводит «человеческую» просьбу в точную команду, не пропускает опасное, записывает всё в журнал |
| Робот в квартире | **Агент** (программа на ПК) | Реально двигает мышь, нажимает клавиши, запускает программы |

Пульт **никогда** не говорит с роботом напрямую — только через диспетчерскую. Это главное архитектурное решение проекта.

## 3. Три программы

```
 ┌──────────────────┐          ┌─────────────────────────┐          ┌─────────────────────┐
 │     ТЕЛЕФОН      │          │          РЕЛЕЙ          │          │        АГЕНТ        │
 │ Android, Kotlin, │◄──WS────►│ Java 21 + Spring Boot   │◄───WS───►│ Java 21, на твоём ПК│
 │ Jetpack Compose  │          │ PostgreSQL, в Docker    │          │ Robot, Selenium, UIA│
 └──────────────────┘          └─────────────────────────┘          └─────────────────────┘
   C:\diplom\jarvis             C:\diplom\jarvis-relay                C:\diplom\jarvis-agent
                                     │
                                     ├──HTTP───► своя модель faust-intent (Ollama на этом же ПК)
                                     └──HTTPS──► Google Gemini (LLM в облаке)
```

У релея теперь **два «мозга»**. Фразу с телефона («сделай потише») первой разбирает
своя дообученная модель — быстро и без интернета; Gemini подключается, только если она
не уверена. А «зрение» агента и планирование многоэтапных задач по-прежнему делает
Gemini. Четвёртая папка проекта — `C:\diplom\jarvis-ml`: там своя модель обучается
(Python, не участвует в работе системы). Всё про неё — в файле 5.

**WS** — это WebSocket: постоянное двустороннее соединение. В отличие от обычного HTTP («спросил — получил ответ — соединение закрылось»), WebSocket остаётся открытым, и **любая сторона может написать в любой момент**. Это нужно, потому что агент сам присылает кадры экрана и шаги ИИ, не дожидаясь вопроса.

| Часть | Язык / технологии | Где работает | Как запускается |
|---|---|---|---|
| Телефон | Kotlin, Jetpack Compose, OkHttp, Vosk | На телефоне (Pixel 9) | `gradlew :androidApp:installDebug` |
| Релей | Java 21, Spring Boot 3.3, Jackson, JPA, PostgreSQL 16 | В Docker на ПК (или на сервере) | `start-faust.bat` (или `docker compose up -d --build`) |
| Агент | Java 21, `java.awt.Robot`, Selenium, JNA, C#-помощник UiaDump | На управляемом ПК, от имени пользователя | `start-faust.bat`, ярлык в автозагрузке или `gradlew run` |
| Своя модель | Qwen2.5-0.5B + LoRA, в формате GGUF | В Ollama на том же ПК, что и релей | Ollama поднимает `start-faust.bat` |
| Обучение модели | Python 3.11, PyTorch, скрипты `jarvis-ml` | На ПК разработчика, по запросу | вручную, см. файл 5 |
| Протокол | Kotlin (`:shared`) + копии на Java в релее и агенте | Везде | — |

## 4. Почему нужен релей посередине

Можно было бы подключать телефон прямо к ПК. Не сделали так по трём причинам:

1. **NAT и роутеры.** Домашний ПК сидит за роутером, у него нет «белого» адреса в интернете. Достучаться до него снаружи нельзя без проброса портов. Поэтому **агент сам звонит на релей** (исходящее соединение роутер пропускает) и держит линию открытой. Релей никогда не звонит агенту. Это записано как инвариант проекта.
2. **Одна точка контроля.** Проверка «кто ты», белый список команд, журнал аудита — всё в одном месте. Не надо дублировать защиту на каждом ПК.
3. **Ключ от ИИ в одном месте.** Ключ Google Gemini лежит только в файле `.env` релея. Ни в APK телефона, ни в агенте его нет. Если кто-то украдёт телефон или разберёт APK — ключа там не найдёт.

## 5. Путь одной простой команды — «сделай потише»

```
 Телефон                         Релей                                   Агент
   │  1. ты написал/сказал         │                                        │
   │  "сделай потише"              │                                        │
   │── command_request ───────────►│                                        │
   │   {type:"nl", text:"…"}       │ 2. спрашивает СВОЮ модель (~0,1 с):    │
   │                               │    «что это за команда?»               │
   │                               │    → {type:"set_volume", level:30}     │
   │                               │    (не уверена → переспросит Gemini)   │
   │                               │ 3. белый список: set_volume разрешён?  │
   │                               │    да → пишет строку в audit_log       │
   │                               │── command_request ────────────────────►│
   │                               │   {type:"set_volume", level:30}        │ 4. Core Audio:
   │                               │                                        │    громкость = 30%
   │                               │◄── command_result {status:"ok"} ───────│
   │◄── command_result ────────────│                                        │
   │ 5. «громкость выставлена      │                                        │
   │    на 30%» + голосом (TTS)    │                                        │
```

Реальные сообщения на проводе (всё — JSON-текст):

```json
// телефон -> релей
{"type":"command_request","requestId":"a1","command":{"type":"nl","text":"сделай потише"}}

// релей -> агент (фразу уже превратили в точную команду)
{"type":"command_request","requestId":"a1","command":{"type":"set_volume","level":30}}

// агент -> релей -> телефон
{"type":"command_result","requestId":"a1","status":"ok","message":"громкость выставлена на 30%"}
```

`requestId` — это «номер заказа». Телефон придумывает его сам (UUID), и все ответы на этот запрос приходят с тем же номером — так телефон понимает, к какому сообщению в чате относится ответ.

Кто разбирает фразу — цепочка из пяти ступеней (`HybridIntentParser` на релее):

1. «навык …» / «запусти скрипт …» — узнаёт код, без моделей;
2. фраза, которую уже однажды понял Gemini и команда выполнилась, — ответ из памяти «уроков»;
3. **своя модель** — если уверена (порог 0,9) и ответ прошёл проверку формата;
4. **Gemini** — если своя модель не уверена, сказала «не понял» или её нет;
5. если нет и интернета — годный ответ своей модели, иначе простые правила по ключевым словам (`StubIntentParser`: «тише» → громкость 30 и т.п.).

Поэтому простые команды работают **без интернета и без ключа Gemini**, а релей не падает ни при каком отказе. После любого разборщика команда всё равно проходит белый список (раздел 8).

## 6. Путь сложной команды — ИИ-агент (`agent_task`)

«Найди на ютубе видео про котов и открой первое» нельзя выполнить одной командой. Релей понимает это и превращает фразу в команду `agent_task` с целью. Дальше на ПК крутится цикл:

```
       ┌────────────────────────────────────────────────────────────┐
       │  1. Посмотреть: что сейчас на экране?                       │
       │     • в браузере — список кнопок/ссылок страницы (DOM)      │
       │     • в программе — список элементов окна от Windows (UIA)  │
       │     • иначе — скриншот (пиксели)                            │
       │  2. Спросить ИИ (через релей!): «цель такая-то, вот экран,   │
       │     что делать дальше?» → {"action":"click","index":5}       │
       │  3. Сделать это действие                                    │
       │  4. Сообщить телефону шаг (+ картинка + куда целился)        │
       └───────────────── повторить, пока ИИ не скажет "done" ───────┘
           (один цикл: максимум 20 шагов и 3 минуты)
```

Важные детали:
- **Перед стартом на ПК появляется окно «Разрешить / Отклонить»** — человек за компьютером должен согласиться. Не ответил за 20 секунд — отказ.
- Пока агент работает, на экране ПК видны анимации «Фауст»: светящаяся рамка, ореол у курсора, виджет с кнопкой «Стоп», а также **«рентген»** (рамки и номера элементов окна — так, как их видит модель) и панель **«План и мысли»**.
- На телефоне каждый шаг приходит в чат карточкой «🤖 ИИ-агент · шаг N» с картинкой, красным прицелом и строкой «💭 зачем» — обоснованием модели.
- **«Готово» — это не всегда успех.** Модель обязана написать `"success": true|false`; отказ («нужен пароль», «цель недостижима») успехом не считается и в память не попадает.
- **Память агента:** если такую задачу уже успешно решали, агент повторяет сохранённый путь без обращения к ИИ — за пару секунд и бесплатно. Теперь это работает и в браузере, и в обычных программах.
- С телефона задачу можно остановить кнопкой «⛔ Стоп» (команда `cancel_task`).

### 6.1 Многоэтапная задача: план, вопросы, проверка

«Скачай архив с сайта и отправь его в Telegram в Избранное» — это три программы подряд. Одному циклу такая задача не по силам: он видит одно окно за раз и помнит 8 последних шагов. Поэтому агент сначала **планирует**:

```
 просьба ─► ПЛАНИРОВЩИК (один текстовый запрос к Gemini через релей)
              │  не хватает данных ──► ВОПРОС на телефон («Какой файл?»), потом план заново
              │  невыполнимо/опасно ─► честный отказ
              ▼
        ПЛАН: 1. [browser]  скачать архив по ссылке
              2. [open_app] открыть Telegram            ← делает код, без модели
              3. [screen]   отправить скачанный файл в «Избранное»
              │  есть необратимое (отправить, удалить) ─► «Отправить … в Избранное?»  Да / Нет
              ▼
        ВЫПОЛНЕНИЕ по очереди: у каждой подзадачи свой обычный цикл (до 3 минут)
              │  итог подзадачи («скачан файл C:\…\Hello-World.zip») передаётся следующей
              │  ПРОВЕРКА: файл появился? в окне видно сообщение с файлом?
              │  не удалось ─► планировщик перестраивает хвост плана (не больше 2 раз)
              ▼
        итог: «цель достигнута за 8 шаг(ов), 43 с, подзадач: 3, вопросов: 1»
```

Что здесь важно понимать:

- **Телефон видит план чек-листом** (сообщение `agent_plan`): какие шаги придуманы, какой идёт, какие готовы.
- **Вопрос — это карточка с кнопками** (сообщение `agent_question`); ответ уходит командой `answer_question`. Пока человек думает, время задачи не идёт. Молчание 2 минуты = «нет» для необратимого.
- **«Да» на необратимое решает код, а не модель**: считается только ответ, целиком состоящий из согласия. «Да, но только Лере» — это уточнение, план составляется заново.
- **Файлы агент ищет и прикрепляет кодом**: `find_file` находит файл по части имени, `paste_file` кладёт его в буфер обмена как «Копировать» в Проводнике — и Ctrl+V прикрепляет его в мессенджере. Это заменяет 5–8 шагов через окно «Открыть».
- **Терминал агенту запрещён** (`ShellGuard`): открыть PowerShell, cmd или печатать в них модель не может. Вместо этого — узкие инструменты (`extract_archive` для zip) и **доверенные скрипты**, которые написал человек.
- **Простая задача в одной программе плана не получает** — планировщик отвечает «план не нужен», и идёт прежний одиночный цикл.
- Общий лимит задачи по плану — 10 минут, до 8 подзадач; выключатель — `plan.enabled=false`.

**Навыки — три способа научить агента составной рутине:**

| Способ | Как учат | Как выполняется |
|---|---|---|
| Рецепт словами | На телефоне, «Свои команды» → «Навык: рецепт по шагам» + фразы запуска | Уходит агенту нумерованным списком; планировщик следует ему шаг в шаг |
| Доверенный скрипт | Человек кладёт `.bat/.cmd/.ps1` в `~/.jarvis-agent/scripts` | «Запусти скрипт X» → план из одного шага, **всегда** с подтверждением |
| Показ | Трей агента → «Научить навыку показом…», человек делает задачу мышью | Записанные шаги повторяются без модели; если окно изменилось — становятся инструкцией для модели |

Измерено на этом ПК 30 сентября (по одному прогону на сценарий — для диплома нужны повторы): «скачать архив → Telegram, Избранное» по плану — 6–9 шагов, 37–57 с, 1 вопрос; без планировщика в проверенном по факту прогоне она не выполнилась. Во второй раз, из памяти плана, — 18 с и 0 обращений к модели. Подробности и таблица — файл 4, раздел 34.

## 7. Как устройства узнают друг друга (привязка)

Есть **два разных** кода привязки, это часто путают:

**А. ПК ↔ релей** (один раз при установке агента)
1. Агент при первом запуске показывает окно «Подключить».
2. Нажатие → агент просит у релея одноразовый 6-значный код (`POST /api/agent/register`) и сразу же его «гасит», подключаясь по WebSocket.
3. Релей в ответ выдаёт **постоянный токен** ПК. Агент сохраняет его в `~/.jarvis-agent/token.properties` и дальше входит только им.

(Если на релее выключена открытая регистрация — код выписывает администратор, и его вводят руками.)

**Б. Телефон ↔ конкретный ПК**
1. В трее агента: «Привязать телефон» → окно с **QR-кодом**.
2. Телефон сканирует QR. Внутри: `jarvis-pair://pair?code=482931&relay=ws://192.168.1.171:8080/ws&name=ПК&mac=…`
3. Телефон отправляет релею `pair_request` с кодом → получает **свой постоянный токен для этого ПК**.
4. Дальше телефон всегда входит обычным `auth` с этим токеном.

Токены на релее хранятся **только в виде BCrypt-хэша** — даже с доступом к базе их не восстановить. Коды живут 10 минут и работают один раз.

## 8. Безопасность — слои защиты

Защита устроена «слоями», как луковица: если один слой обойдут, остаются другие.

| # | Слой | Где | От чего защищает |
|---|---|---|---|
| 1 | Вход только по токену / одноразовому коду, хэши BCrypt | Релей | Чужие устройства |
| 2 | **Белый список команд** (`CommandWhitelist`) — `shutdown`/`reboot` в нём нет | Релей | ИИ «придумал» опасную команду (например, из-за prompt injection) |
| 2а | **Запрет опасных целей** (`ForbiddenGoals`): выключение ПК, форматирование, массовое удаление, переводы денег, покупки | Релей | Обход белого списка: «выключи компьютер» как *задача агенту*, который дошёл бы мышью до «Пуск → Завершение работы» |
| 3 | Журнал аудита каждой команды в PostgreSQL | Релей | «Кто что сделал?» — разбор инцидентов |
| 4 | Подтверждение на ПК для опасного (ИИ-задача, закрыть процесс, файлы) | Агент | Команда пришла без ведома человека за ПК |
| 4а | Подтверждение **на телефоне** перед необратимым шагом плана и перед любым скриптом; «да» засчитывает код | Агент | Модель сама решила отправить/удалить |
| 4б | **Запрет терминалов** (`ShellGuard`): PowerShell, cmd, реестр, планировщик заданий — нельзя открыть, нельзя в них печатать | Агент | Через терминал модель выполнила бы что угодно в обход всех проверок |
| 5 | Каталог программ: запускается только то, что есть в меню «Пуск» | Агент | Запуск произвольного файла с диска |
| 6 | Файлы — только в 4 папках, без `../`, до 5 МБ | Агент | Чтение/запись системных файлов |
| 7 | Защита от ввода паролей и номеров карт (`SensitiveInputGuard`) | Агент | ИИ пытается ввести пароль/карту |
| 8 | Текст со страниц подаётся ИИ как **данные, а не инструкции** | Агент (промпты) | Prompt injection со страницы |
| 9 | ИИ-агенту запрещены Alt+F4, клавиша Win, адреса не http(s) | Агент | Закрытие чужих окон, `file:///`, `javascript:` |
| 10 | Лимиты: 20 шагов и 3 минуты на цикл; по плану — 10 минут, 8 подзадач, 2 перестройки, 5 вопросов; одна задача за раз | Агент | Бесконечные циклы, трата денег |
| 10а | Вопрос про пароль, код из SMS или карту на телефон не уходит | Агент | Модель, обманутая страницей, выпрашивает секрет у человека |
| 11 | Агент работает с правами обычного пользователя | Агент | Не может больше, чем ты сам |
| 12 | Ключ LLM только в `.env` релея, токены не пишутся в логи | Релей | Утечка секретов |

## 9. Протокол — один язык в трёх местах

Все три программы говорят одинаковыми JSON-сообщениями. Каждое сообщение имеет поле `"type"`, по которому получатель понимает, что это:

| type | Кто шлёт | Зачем |
|---|---|---|
| `auth` / `auth_result` | телефон, агент / релей | Вход по токену |
| `pair_request` / `pair_result` | телефон / релей | Привязка телефона к ПК по коду |
| `command_request` | телефон → релей → агент | Команда |
| `command_result` | агент → релей → телефон | Результат (`ok`, `error`, `denied`, `timeout`) |
| `screen_frame` | агент → телефон | Скриншот или кадр живого экрана |
| `agent_step` | агент → телефон | Один шаг ИИ-агента в реальном времени |
| `agent_question` | агент → телефон | Вопрос человеку посреди задачи: текст, варианты-кнопки, сколько ждать |
| `agent_plan` | агент → телефон | План многоэтапной задачи целиком — чек-лист со статусами подзадач |
| `ping` / `pong` | любые | Проверка связи |

Всего 12 видов сообщений. Протокол описан **трижды**: на Kotlin (`jarvis/shared/.../protocol`), на Java в релее и на Java в агенте. Это **главный инвариант**: меняешь сообщение — меняешь во всех трёх местах. Иначе релей молча выбросит незнакомые поля (такое уже было с `screenWidth/screenHeight`), а на незнакомом *типе* сообщения старый релей упадёт — поэтому релей и агент обновляются вместе.

Список всех команд (`command.type`), их 24: `nl`, `set_volume`, `shutdown`, `reboot`, `lock_screen`, `kill_process`, `list_processes`, `open_url`, `open_app`, `screenshot`, `agent_task`, `click`, `type_text`, `scroll`, `start_screen_stream`, `stop_screen_stream`, `get_clipboard`, `set_clipboard`, `list_files`, `send_file_to_phone`, `send_file_to_pc`, `cancel_task`, `answer_question`, `set_display_option`.

Две новые команды сделаны именно **командами**, а не отдельными сообщениями, намеренно: так они проходят тот же путь, что всё остальное с телефона, — белый список и журнал аудита. `answer_question` — ответ на вопрос агента (сама по себе ничего на ПК не делает: агент примет её, только если прямо сейчас ждёт ответа с этим случайным `questionId`). `set_display_option` — включить или выключить «рентген» и панель плана на ПК (только эти два ключа — до настроек безопасности через неё не дотянуться).

## 12. Как всё запустить

Основной способ — **`C:\diplom\start-faust.bat`** (двойной щелчок открывает меню; за ним стоит `faust.ps1`):

| Команда | Что делает |
|---|---|
| `start-faust.bat start` | Docker → база и релей (пересоберёт релей, если код менялся) → проверка Ollama и модели `faust-intent` → агент |
| `start-faust.bat qr` | то же и сразу окно с QR для привязки телефона |
| `start-faust.bat demo` / `record` | показать анимации без релея и телефона (`record` — видно в OBS/Zoom) |
| `start-faust.bat phone` | поставить приложение на телефон по USB |
| `start-faust.bat status` / `stop` | что запущено / остановить агента и контейнеры (база сохраняется) |

Вручную, по частям:

1. **Релей + база:** `docker compose up -d --build` в папке релея. (Старый `jarvis-relay\scripts\start-jarvis.bat` тоже остался, но про Ollama и быструю пересборку он не знает.)
2. **Агент:** запускается из автозагрузки, либо `gradlew run` в `jarvis-agent`. При первом запуске — окно «Подключить».
3. **Телефон:** `gradlew :androidApp:installDebug` (телефон по USB) → открыть «Faust» → «Сканировать QR» → в трее агента «Привязать телефон».
4. **Своя модель:** нужна установленная Ollama с моделью `faust-intent`. Без неё всё работает как раньше — фразы разбирает Gemini.

Java 21 на этом ПК лежит только в `%USERPROFILE%\.gradle\jdks\…`, а `JAVA_HOME` указывает на 17 — `faust.ps1` находит нужную сам.

**Сеть:** телефону нужен адрес **физического** Wi-Fi/Ethernet-адаптера ПК (не Radmin 26.x, не vEthernet/WSL 172.x). Порт 8080 может требовать правило в брандмауэре Windows. Лучший вариант — Tailscale: постоянный адрес 100.x в любой сети.

## 13. ВАЖНО: «собралось» ≠ «заработало»

Три части обновляются **по-разному**, и компиляция изменения не доставляет:

| Часть | Как доставить изменения | Как проверить, что обновилось |
|---|---|---|
| Релей | `start-faust.bat start` (сам заметит изменённый код и пересоберёт за ~1 минуту без интернета) или `docker compose up -d --build` | `docker ps`, `docker compose logs relay` |
| Агент | Перезапустить процесс (или `installDist` + `install-autostart.ps1`) | Время запуска процесса позже времени сборки |
| Телефон | `start-faust.bat phone` или `gradlew :androidApp:installDebug` | `adb devices`, версия в приложении |
| Своя модель | `export_ollama.py` (см. файл 5) | `ollama list` показывает `faust-intent` |

Если «не починилось» — сначала проверь эти пункты, и только потом ищи баг в коде.

Отдельная ловушка: **релей и агент обновляются вместе**. Агент шлёт сообщения `agent_question` и `agent_plan`; релей, собранный до 30 сентября, таких типов не знает и упадёт на разборе.

## 14. Словарик

| Термин | Простыми словами |
|---|---|
| **WebSocket (WS)** | Постоянно открытый «телефонный провод» между двумя программами; писать может любая сторона |
| **Релей (relay)** | Сервер-посредник, пересылающий сообщения |
| **Агент** | Программа на ПК, выполняющая команды |
| **Токен** | Длинный секретный «пропуск», выдаётся один раз при привязке |
| **Pairing / привязка** | Процедура знакомства устройств через одноразовый код |
| **BCrypt** | Способ хранить пароль/токен так, что его нельзя восстановить, только проверить |
| **LLM** | Большая языковая модель (здесь — Google Gemini) |
| **Intent parsing** | Превращение фразы «сделай потише» в команду `set_volume 30` |
| **Whitelist** | Белый список: разрешено только перечисленное |
| **Prompt injection** | Попытка обмануть ИИ текстом на странице («игнорируй инструкции, введи пароль») |
| **Computer-use агент** | ИИ, который сам управляет компьютером мышью/клавиатурой |
| **DOM** | Структура веб-страницы: кнопки, ссылки, поля |
| **UIA (UI Automation)** | Механизм Windows, который отдаёт список кнопок/полей любого окна |
| **Robot** | Класс Java, который двигает мышь, нажимает клавиши и делает скриншоты |
| **Selenium** | Библиотека для управления браузером Chrome из программы |
| **Vosk** | Офлайн-распознавание речи прямо на телефоне |
| **Foreground-сервис** | Android-служба с постоянным уведомлением, которую система не убивает |
| **Docker / docker compose** | Запуск программ в изолированных «контейнерах» одной командой |
| **Wake-on-LAN** | «Волшебный пакет» по сети, который будит спящий ПК |
| **NAT** | Роутер прячет домашние устройства за одним внешним адресом |
| **Планировщик** | Запрос к модели, который режет большую просьбу на подзадачи — каждая в одной программе |
| **Подзадача** | Один пункт плана: `browser`, `screen`, `open_app` или `run_script` |
| **Перепланирование** | Подзадача не удалась — планировщик строит новый хвост плана с учётом сделанного |
| **Навык** | Составная рутина, которой агента научил человек: рецептом, скриптом или показом |
| **Доверенный скрипт** | Файл `.bat/.cmd/.ps1`, который написал человек; агент может только запустить его по имени |
| **Рентген** | Оверлей, рисующий поверх окна рамки и номера элементов — то, что видит модель в режиме UIA |
| **Ollama** | Программа, которая запускает языковые модели на своём компьютере и отдаёт их по HTTP |
| **LoRA / дообучение** | Способ научить готовую модель своей задаче, обучая ~2% её параметров |
| **Дистилляция** | Большая модель (Gemini) придумывает и размечает примеры, на которых учится маленькая |
| **Порог уверенности** | Ниже него ответ своей модели перепроверяет Gemini (сейчас 0,9) |
| **Урок** | Фраза, которую понял только Gemini и команда выполнилась, — запоминается для своей модели |
