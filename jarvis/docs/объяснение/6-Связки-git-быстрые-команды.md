## 1. Коротко: что сделано

| Что | Как звучит | Где в коде |
|---|---|---|
| Git: status, pull, commit, push | «запушь демо», «закоммить и запушь» | `GitTool`, `DevTools`, `RepoCatalog` |
| Правка кода | «поменяй порт в docker-compose на 8090 и запушь» | `CodeAgent` (Claude Code без терминала) |
| Быстрые команды | «пауза», «следующий трек», «громче на 20%», «сверни все окна» | релей `QuickPhrases`, агент `quickAction` |
| Составные фразы | «сделай потише и открой ютуб» | релей `HybridIntentParser.composite`, агент `sequence` |
| Для каждого из списка | «отправь одногруппникам отчёт» | `RecipientLists`, `GeminiTaskPlanner` (for_each) |
| Дождаться | «дождись конца сборки и напиши» | шаг WAIT в `PlanRunner` |
| Продолжить | «Фауст, продолжи» | `ResumeStore`, `PlanRunner.withResume` |
| Отчёт | «…без обращений к ИИ; итог: отправлено main → origin/main» | `CommandExecutor.resultNote`, счётчик `RelayLlmClient.calls` |

Главная идея везде одна: **модель выбирает, код исполняет и проверяет.** Модель может
сказать «сделай push в репозиторий демо» или «повтори для списка одногруппники», но путь к
папке, список людей, текст команды git и решение «можно ли» — у кода.

## 2. Git с телефона

**Как работает.** Человек сам перечисляет разрешённые репозитории в файле
`~/.jarvis-agent/repos.txt`, по строке на проект: `демо = C:\Users\я\FaustGitTest\demo`.
Агент работает только с ними. Планировщик видит названия, но не пути.

Операций четыре: `status`, `pull`, `commit`, `push`. Их выполняет `GitTool` — Java запускает
программу `git` напрямую, с фиксированными аргументами, без cmd и PowerShell. Сообщение
коммита передаётся через стандартный ввод (`git commit -F -`), поэтому никакой текст от модели
не может стать командой.

**Почему это не нарушает запрет терминала.** Терминал запрещён (ShellGuard), потому что в нём
модель пишет любую команду. Здесь команду собирает код, а модель выбирает одну из четырёх
операций — как кнопку.

**Подтверждение — в момент коммита и с диффом.** Обычный план подтверждается целиком в
начале. С кодом так нельзя: до правки неизвестно, что изменится, и «Да» на неизвестное ничего
не стоит. Поэтому вопрос задаётся при коммите, и в нём показаны список файлов и сами строки
изменений. Если сразу за коммитом идёт push того же репозитория, вопрос один на оба шага: два
«Да» подряд приучают нажимать не читая (то же наблюдение, что 30.09 с тремя подтверждениями).

**Защиты.**
- Без «Да» ничего не коммитится и не отправляется; молчание — это «нет». После отказа индекс
  возвращается как был, правки на диске остаются целыми.
- Файлы с секретами (`.env`, ключи, сертификаты, `token.properties`) в коммит не попадают
  никогда: коммит отменяется целиком, человека даже не спрашивают. `.env.example` разрешён —
  это образец без значений.
- git не может спросить пароль (`GIT_TERMINAL_PROMPT=0`): без входа push честно падает,
  а не висит.
- `pull` только перемоткой: если ветки разошлись, агент сам не сливает, а говорит человеку.
- «Нет» на коммите останавливает весь план — перестраивать его «в обход» отказа нельзя
  (`PlanRunner.Declined`).

**Без планировщика.** «git status демо», «запушь демо», «закоммить и запушь демо» релей сразу
отдаёт агенту (`StubIntentParser`), а агент сразу строит готовый план (`DevTools.preset`).
Ни Gemini, ни своя модель не нужны, работает без интернета. Живой прогон: **2 шага, 1–2 с,
1 вопрос, 0 обращений к ИИ**; коммит дошёл до «сервера» — голого репозитория на том же ПК.

## 3. Агент для кода

Править код по смыслу — задача другого масштаба: прочитать проект, найти место, аккуратно
изменить. Для этого есть готовые агенты (Claude Code, Gemini CLI, Aider). «Фауст» здесь
диспетчер: решает, где можно работать и что можно делать, и показывает итог человеку.

`CodeAgent` запускает Claude Code без окна (`claude -p`) в папке разрешённого репозитория.
Задача передаётся через стандартный ввод: в командной строке Windows кириллица и кавычки
ломаются. Инструменты выдаются только такие: `Read, Edit, Write, Glob, Grep`. **Терминала у
него нет вовсе** — он не может собрать проект, сделать push или сходить в интернет. Читать и
править `.env` тоже запрещено.

Что изменил агент для кода, «Фауст» узнаёт не с его слов, а по диску: снимает отпечатки
(`git hash-object`) изменённых файлов до и после работы. Так видна правка даже в файле,
который был изменён ещё до агента.

**Где ключ.** Это осознанное исключение из правила «ключ модели только на релее»: агент для
кода работает под учётной записью самого пользователя на его же ПК — он один раз входит в
Claude Code. В коде и настройках «Фауста» ключа нет. Какую программу запускать, задаёт
`code.command` (можно поставить другую).

Пример полной связки: «поменяй порт web в docker-compose демо на 8090, закоммить и запушь» →
планировщик: `[code] демо: порт 8090` → `[git] commit «Порт 8090»` → `[git] push`.

### 3а. Обновление 20.10: работа с проектами всерьёз

**Встроенный редактор (`GeminiCodeEditor`).** Claude Code на ПК требует отдельного входа, а
на этом ПК он вышел из аккаунта. Поэтому появился второй редактор — через Gemini на релее,
тем же путём, что весь агент: ключ остаётся на релее, инвариант не нарушается.
- Маленький проект модель получает целиком, большой — сначала списком файлов, и сама выбирает
  до 6 нужных.
- Ответ — пары «было → стало». Код применяет пару, только если «было» встречается в файле
  ровно один раз. Сначала проверяются все пары и лишь потом что-то пишется: полправки не бывает.
- Концы строк файла (CRLF на Windows) сохраняются. Писать вне проекта, в `.git` и в файлы с
  секретами нельзя.

Какой редактор брать, задаёт `code.engine`. `auto` пробует Claude Code; если тот не
установлен или не вошёл, берёт встроенный и 10 минут не тратит время на повторные попытки.
Живой прогон «правка в демо: поменяй порт на 8090»: **9 с, 1 обращение к ИИ**, в диффе ровно
одна изменённая строка, коммит дошёл до «сервера».

**Сообщение коммита** берётся из описания правки (первая фраза, до 72 символов) — «Изменен
внешний порт сервиса web на 8090», а не безликое «изменения».

**Три ответа вместо двух.** Если за коммитом идёт push, вопрос предлагает «Да» (коммит и
push), «Только коммит» и «Нет».

**Новые операции git:** история (`log`), ветка (перейти или создать; имя проверяет сам git),
откат несохранённых правок (`discard` — только с «Да», с перечнем файлов; новые файлы не
удаляются).

**Экран «Проекты» в приложении.** Команда протокола `dev_repos` → ответ `repo_list`: проекты
с веткой, изменёнными файлами, «не отправлено / на сервере новее», последним коммитом. Только
чтение и без путей на диске. Кнопки карточки — Коммит и push, Push, Pull, История, Ветка…,
Откатить — и поле «Что поменять в коде?». Всё это обычные задачи агенту с готовой формулировкой:
агент узнаёт их без модели. Сверху экрана — «Ход задачи»: план, вопрос с подсвеченным диффом
(зелёные и красные строки, моноширинно) и итог. Подтвердить коммит можно, не уходя в чат.
После задачи карточки обновляются сами.

### 3б. Обновление 11.11: тесты, исправление по ошибке, запасной редактор, показ в IDE

**Сначала замер.** План был — управлять встроенными ИИ-помощниками сред разработки (Gemini в
Android Studio, AI Assistant в PyCharm) через их окна. Замер: UI Automation видит в окне
Android Studio **0 элементов**. Среды JetBrains рисуют интерфейс сами (Swing) и отдают его
наружу только через Java Access Bridge — это другой механизм, агент его не читает. Остались бы
только снимки экрана в Gemini: медленно, платно за каждый шаг, хрупко при печати промпта в
чужой чат. Поэтому от этой идеи отказались, а сделали четыре вещи ниже.

**1. Разрешённые команды проектов** (`RepoCommands`). Человек сам пишет в
`~/.jarvis-agent/repo-commands.txt` строки `демо: тесты = powershell -NoProfile -ExecutionPolicy
Bypass -File tests\check.ps1` или `диплом: тесты = gradlew.bat test`. В плане появляется
операция `run`: «прогнать «тесты» в «демо»». Модель называет **только название** из списка —
командную строку, аргументы и папку задал человек; ни одного символа от модели в команду не
попадает. Это тот же принцип, что у доверенных скриптов, но команда привязана к проекту и
выполняется в его папке. В отличие от скрипта, долгий прогон в фон не уходит: тесты, которые
«ещё идут», ничего не доказывают. Не уложилась в `code.commandTimeoutSec` (600 с) — процесс
останавливается вместе с дочерними (java под gradlew).

**2. Цикл «правка → тесты → исправление → тесты».** «Правка в демо: …» теперь сама вставляет
прогон тестов между правкой и коммитом, если у проекта они описаны. Тесты упали, а в этой
задаче агент для кода правил этот проект — значит, скорее всего, сломала правка. Агенту для
кода уходит исходная задача **вместе с текстом ошибки** (последние строки вывода, до 6000
символов), и тесты прогоняются снова. Попытка одна (`code.fixAttempts`): если модель не
исправила по точному тексту ошибки с первого раза, вторая чаще ломает что-то ещё. Дальше —
человек.
- Не прошли и после исправления — **коммита не будет**, даже если план дойдёт до него в
  обход (страховка в самом коммите); правка остаётся в папке.
- Тесты упали, а агент проект не правил — чинить чужое без спроса нельзя: только отчёт.
- В вопросе о коммите появилась строка «Проверено: «тесты» прошли (12 с)». Человек решает по
  диффу и по тестам. Сообщение коммита — по исходной правке, а не по исправлению.
- На телефон из лога идут только «ключевые» строки (FAIL, error, ошибка, exception) — не
  больше 6.

**3. Запасной редактор чаще.** Раньше на встроенный редактор (Gemini) переходили, только если
Claude Code не установлен или не вошёл. Теперь ещё: кончился лимит, нет доступа по подписке,
завис (не ответил за `code.timeoutSec`), упал без ответа. Что Claude Code успел изменить до
зависания, остаётся на диске и попадает в общий дифф. **Не** переходим, если Claude Code
поработал и сам отказался («задача опасна»): отдавать ту же задачу другой модели в обход
отказа нельзя. В итоге видно, кто правил: «изменено (встроенный редактор, т.к. у Claude Code
кончился лимит)».

**4. Показ правки в IDE** (`IdeView`). После правки изменённые файлы (до трёх) открываются на
изменённой строке официальной командой запуска среды: `studio64.exe --line 12 файл`,
`Code.exe -g файл:12`. Это делает код, без модели и кликов; строку даёт `git diff -U0`.
Среда выбирается по типу проекта (Android — Android Studio, Python — PyCharm, Gradle/Maven —
IntelliJ IDEA, иначе VS Code), но в режиме `auto` — **только если она уже открыта**: тяжёлую
программу агент без спроса не запускает. `always` — запустить, `off` — никогда.

**Живая проверка 11.11.** Команда тестов «демо» (`tests\check.ps1`: порты в docker-compose в
пределах 1–65535, у страницы есть заголовок): на исправном проекте — «прошли»; с портом 99999 —
«не прошли, код 1» и строка `FAIL: port 99999 … out of range`. Claude Code вживую не
проверен: сервер ответил 403 `oauth_not_allowed_for_organization` — «Claude Code can't use
your Claude subscription, usually because a payment is past due». Вход при этом есть
(`claude auth status`), а прежний разбор ответа принял это за «не вошёл» из-за слов «API key» в
тексте — исправлено, теперь причина называется верно. Живой прогон всей связки:
`./gradlew runCodeCheck --args="демо|поменяй внешний порт web на 8095"` (без релея и телефона,
печатает время каждого шага).

## 4. Быстрые команды

Новая команда протокола `quick_action` с закрытым списком действий: `play_pause`,
`next_track`, `prev_track`, `volume_delta` (±N процентов от текущей), `minimize_all`.

**Узнаются правилами, без модели** (`QuickPhrases` в релее): таких фраз немного, звучат они
почти одинаково, а правило отвечает мгновенно и всегда одинаково. Своя модель этой команды не
знает. До этого «громче на 20%» превращалось в «громкость 20», то есть звук становился
**тише** (экзамен Б, фраза b-45).

Правила узкие: фраза должна целиком быть командой. «Сделай потише» без числа по-прежнему
означает абсолютную громкость (как раньше), а «громкость на 20» — «выставь 20».

**На ПК.** Медиаклавиши жмутся через WinAPI `keybd_event`: Windows отдаёт их тому плееру,
который сейчас играет, какое бы окно ни было впереди. Сворачивание — `Win+M`. Для «громче
на N» скрипт Core Audio читает текущую громкость и сдвигает её.

Найденная при проверке ошибка: позиционный аргумент «-5» PowerShell принимает за имя
параметра, и скрипт молча выставлял громкость **0**. Исправлено — параметры передаются по
имени (`-Level -5 -Mode delta`).

## 5. Составные фразы

«Сделай потише и открой ютуб» раньше уходила ИИ-агенту целиком: планировщик, скриншоты,
десятки секунд. Теперь релей режет фразу по «и», «потом», «затем», «а потом» и разбирает
каждую часть **только правилами и своей моделью**, без Gemini. Если **каждая** часть —
простая команда, и модель в каждой уверена (≥ 0,9), получается команда `sequence`. Агент
выполняет её по очереди и отвечает одним итогом. Если хоть одна часть не простая
(«открой почту и найди письмо от Пети»), фраза разбирается целиком, как раньше.

Почему без Gemini: иначе каждая длинная просьба агенту платила бы лишний запрос за попытку
её разрезать.

Защиты: внутри `sequence` только простые команды, не больше 4, без вложенных списков и задач
агенту. Белый список проверяет **каждую** команду внутри (`CommandWhitelist`), агент
проверяет ещё раз сам.

**Замеры (своя модель v3, 19.10):**
- 10 составных фраз: 9 из 9 простых стали правильным списком, а задача агенту («открой
  почту и найди письмо») осталась одной задачей.
- На экзаменах А и Б (451 фраза) ни одна фраза не стала списком по ошибке. Первая версия
  резала по одной запятой и испортила одну фразу («покажи все программы, которые открыты»).
  Поэтому одна запятая больше не граница, а повтор одной и той же команды не считается
  составной фразой.

## 6. «Для каждого из списка»

Буквально «во все чаты» агент не делает: одна ошибка распознавания — и сообщение уходит всем,
отозвать его нельзя. Рассылка идёт только по спискам, которые человек сам составил в
`~/.jarvis-agent/lists.txt`: `одногруппники = Петя, Маша, Лера` (не больше 10 человек).

Планировщик пишет шаги один раз, с `{имя}` вместо имени:
`{"scope":"for_each","list":"одногруппники","steps":[{"scope":"screen","goal":"отправь {имя} отчёт"}]}`.
**Размножает шаги код**, а не модель: модель могла бы пропустить человека или придумать
лишнего. Неизвестный список — отказ с перечнем существующих, а не догадка. Подтверждение
рассылки всегда перечисляет всех получателей поимённо, и это дописывает код. Лимит 8
подзадач размноженные шаги не обрезает: молча обрезанный список пропустил бы людей.

## 7. «Дождись, пока…»

Новый вид шага плана — WAIT. Он ничего не делает, только смотрит, пока не выполнится одно из
условий:
- закрылся процесс («пока закончится сборка» — `process: gradle`), опрос раз в 3 с;
- появился файл (`expect_file`), опрос раз в 3 с;
- на экране видно нужное (`check`) — смотрит модель, не чаще раза в 15 с и не больше 20 раз
  за шаг (это потолок цены ожидания).

Время ожидания не входит в общий лимит задачи, как и время ответов человека. Иначе «дождись
конца сборки» съедало бы весь лимит.

«Когда закончится — напиши мне» — это WAIT, а итог задачи и так приходит на телефон (и
озвучивается).

---

## 8. «Продолжи с места сбоя»

Если план оборвался (шаг не удался и перестроек не осталось, кончилось время, человек отменил),
`PlanRunner` сохраняет в `~/.jarvis-agent/resume.json`, что сделано (с итогами — именами
файлов и т.п.) и что осталось, начиная с упавшего шага. «Фауст, продолжи» — агент спрашивает
«Продолжить задачу «…»? Уже сделано: …; продолжу с шага: …» и идёт дальше. Сделанное не
повторяется, а следующие шаги получают итоги сделанных, как будто обрыва не было.

Не сохраняется, если человек сам сказал «нет». Живёт 3 часа: потом экран и файлы уже другие.
Выполненный план стирает сохранённый. «Продолжи музыку» — это не продолжение задачи, а
пауза/плей (правило в релее).

## 9. Отчёт о задаче

`RelayLlmClient` считает свои запросы. Разница «после задачи минус до» — сколько обращений к
ИИ стоила задача. Эта цифра идёт:
- в итог на телефон: «…, обращений к ИИ: 7» или «…, без обращений к ИИ»;
- в журнал прогонов (`llmCalls`) — это цена задачи для таблиц.

Плюс строка «итог: …» — результат последней подзадачи, то, что человеку важнее всего услышать.
Пример живого итога:

> цель достигнута за 2 шаг(ов), 1 с, подзадач: 2, вопросов: 1, без обращений к ИИ
> итог: «демо»: отправлено: main → origin/main (1 коммит(ов))

## 10. Изменения протокола

Две новые команды во всех трёх копиях (Kotlin `:shared`, релей, агент): `quick_action(action,
amount)` и `sequence(commands)`. Обе — в белом списке релея с проверкой содержимого. Телефону
понимать их не нужно: он шлёт фразу, а получает обычный итог. Приложение на телефоне
пересобирать не обязательно. Kotlin-копия обновлена ради инварианта «протокол синхронно в трёх
местах», тест сериализации проходит, приложение собирается.

git, правка кода, ожидание, списки и продолжение протокол не меняют: это новые виды
подзадач внутри `agent_task`.

## 11. Файлы на диске и выключатели

| Файл | Что |
|---|---|
| `~/.jarvis-agent/repos.txt` | разрешённые репозитории (UTF-8, `имя = путь`) |
| `~/.jarvis-agent/repo-commands.txt` | команды проектов (`репозиторий: название = команда`) |
| `~/.jarvis-agent/lists.txt` | списки получателей (`название = имя, имя`) |
| `~/.jarvis-agent/resume.json` | последний оборванный план (сам) |

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `code.enabled` (agent.properties) | true | агент для кода |
| `code.command` | claude | чем править код |
| `code.timeoutSec` | 300 | сколько ждать одну правку |
| `code.engine` | auto | auto — Claude Code, а при сбое встроенный; claude; gemini |
| `code.commandTimeoutSec` | 600 | сколько ждать команду проекта (тесты, сборку) |
| `code.testBeforeCommit` | true | вставлять тесты в «правка в X: …» перед коммитом |
| `code.autoFix` / `code.fixAttempts` | true / 1 | исправлять по тексту упавших тестов, сколько раз |
| `code.showInIde` | auto | открыть правку в IDE: auto (если открыта), always, off |
| `plan.waitMinutes` | 10 | сколько ждать условия, если не сказано |
| `jarvis.intent.composite` (релей) | true | делить составные фразы |

Пустой `repos.txt` — git и правка кода недоступны. Пустой `lists.txt` — рассылки нет.

## 12. Что проверено, а что нет

  «Да» ничего не коммитится, `.env` не уходит даже с «Да»); for_each, WAIT, продолжение,

- составные фразы — на своей модели v3 в Ollama.

- 11.11, юнит-тестами: команды проектов на настоящем процессе (`.cmd` в репозитории), цикл
  «правка ломает → исправление по тексту ошибки → тесты прошли → коммит дошёл до «сервера»»,
  «не исправилось → коммита нет, вопрос не задан, правка цела», переход на запасной редактор
