# Дальнейшее развитие проекта

После шага 5/5 (фон + уведомления) базовый набор фич закрыт: голос/текст,
конкретные команды, вижн-агент (браузер/экран), живой стрим экрана с точным
тапом, живой просмотр шагов агента, быстрые команды, буфер обмена, файлы
телефон↔ПК, работа в фоне. Ниже — что можно добавлять дальше. Не промпты
для агентов (это не готовые к исполнению диффы, а список идей), а материал,
чтобы выбрать следующие шаги и заодно раздел «дальнейшее развитие» в диплом.
Сгруппировано по смыслу, внутри каждой группы — примерно по убыванию
«отдача / сложность».

## 1. Удобство использования

- **Многошаговый диалог с контекстом.** Сейчас каждая фраза — независимая
  команда. Можно научить релей понимать «сделай то же самое ещё раз» или
  «а теперь на весь экран», опираясь на предыдущие 1-2 реплики в чате.
- **История задач отдельным экраном.** `AgentReport.trace` уже собирается,
  но нигде не хранится — только мелькает в чате. Отдельный экран
  «Журнал задач» с полным трейсом каждой + возможностью открыть скриншоты
  шагов задним числом — и полезная фича, и готовый материал для раздела
  диплома про аудит/логирование.
- **Отмена активной задачи.** Пока `agent_task` запущен на несколько минут,
  единственный способ его прервать — закрыть приложение/агент. Кнопка
  «Стоп» с новой командой `cancel_task(requestId)` была бы куда безопаснее.
- **Голосовой wake-word** («Джарвис, …») вместо тапа по микрофону — ближе к
  реальному «вау-эффекту» голосового ассистента, требует постоянно
  работающего распознавания в фоне (аккуратно с батареей).

## 2. Безопасность и доверие (хорошо ложится в главу про threat model)

- **Подтверждение чувствительных команд на самой ПК.** Сейчас whitelist —
  единственный барьер. Для опасных операций (`kill_process`, `shutdown`,
  запись файла поверх существующего) можно добавить локальный диалог на ПК
  «Джарвис хочет сделать X — разрешить?» с коротким таймаутом. Это отдельный
  рубеж защиты: даже если whitelist и LLM ошиблись, финальное слово — за
  человеком у экрана.
- **Биометрия/PIN на телефоне** перед отправкой особо чувствительных команд
  (например, `shutdown` или отправка файла с ПК, если он окажется вне
  разрешённых папок из `FileCatalog`).
- **Журнал отклонённых команд.** `CommandWhitelist` уже отклоняет всё вне
  списка — но эти отказы нигде не видны пользователю системно. Отдельный
  «Security log» (кто/когда/что пыталась сделать LLM и было отклонено) —
  прямая демонстрация работы защиты для комиссии.
- **Шифрование поверх транспорта.** Сейчас безопасность держится на
  TLS/токене релея. Доп. слой (например, подпись/шифрование самого
  содержимого команды ключом, известным только паре телефон-ПК) — тема для
  обсуждения даже если не будет реализована полностью, как «что можно
  усилить».

## 3. Архитектура и масштаб

- **Несколько ПК одновременно.** Сейчас `activeDevice` — один ПК за раз.
  Расширение: рассылка одной команды на несколько привязанных машин
  («выключи звук на всех ПК») или явное переключение в самом сообщении
  («на домашнем ПК открой...»).
  - Ирония: `AppScreen.DEVICES` уже есть как экран управления списком
    привязанных ПК — расширение свойств, а не новая подсистема.
- **Веб-панель в дополнение к телефону**, использующая тот же
  WebSocket-протокол relay — например, чтобы следить за ходом задачи с
  ноутбука или показать демо на защите с большого экрана без телефона в
  кадре.
- **LAN-режим без облачного relay.** Если телефон и ПК в одной сети,
  напрямую соединяться по локальному адресу — ниже задержка, работает без
  интернета, отдельный аргумент в главу про производительность.
- **Метрики и дашборд.** Сбор задержки (отправка → первый ответ), процента
  `DENIED`/`ERROR`, среднего числа шагов `agent_task` до завершения — уже
  тема для эмпирической главы диплома («оценка эффективности агента»), а не
  просто фича.

## 4. Возможности агента

- **Специализированные адаптеры под популярные приложения** (Spotify:
  пауза/трек, YouTube: лайк/подписка, почта: «прочитай последнее письмо») —
  как прямые команды в обход вижн-агента там, где он не нужен: быстрее и
  надёжнее, чем гонять модель по экрану ради простого действия.
- **Запись макроса.** «Запомни, что я сейчас делаю» → агент фиксирует
  последовательность кликов/текста и потом воспроизводит её по одной
  голосовой команде — полезно для повторяющихся рутинных действий.
- **Мультиязычность NL-парсинга.** Сейчас быстрые фразы заточены под
  русский + немного английского (`StubIntentParser`) — можно обобщить на
  произвольный язык через сам LLM вместо шаблонных фраз.

## Как выбрать, что дальше

Пиши/спрашивай в любом порядке — предыдущий подход (по одной фиче за
раз, а мелкие — вместе) работал хорошо, можно продолжать так же. Если
нужен ориентир: с точки зрения диплома лучше всего «закрывают» тему —
подтверждение чувствительных команд на ПК (усиливает главу про
безопасность) и метрики/дашборд (даёт эмпирику для оценки), а с точки
зрения демонстрации на защите — отмена активной задачи и история задач
(наглядно показывают, что система не «чёрный ящик»).
