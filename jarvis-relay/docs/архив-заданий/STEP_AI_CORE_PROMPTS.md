# Jarvis — шаг «AI-ядро»: умный разбор фраз + vision-агент

Это центральная часть диплома (тема A8: «AI-агент для автоматизации многоэтапных пользовательских задач»).
Как пользоваться: каждому ИИ-агенту давай **«Общий контекст»** + **промпт своего подпроекта**.
Порядок: **0 (ты сам) → Релей → Агент → Приложение**. Каждый этап проверяется отдельно.

---

## Шаг 0 — делаешь сам (5 минут)

1. Зайди в **Google AI Studio** (aistudio.google.com) под Google-аккаунтом → **Get API key** → **Create API key**. Карта не нужна: у Gemini API есть бесплатный уровень с лимитами запросов в минуту и в день.
2. Там же, в списке моделей, посмотри актуальные названия моделей **Flash** и **Flash-Lite**. Например, `gemini-2.0-flash` уже снята с поддержки, поэтому нужна текущая.
3. Открой `C:\diplom\jarvis-relay\.env` и впиши:
   ```
   JARVIS_LLM_API_KEY=<твой ключ>
   JARVIS_LLM_MODEL=<актуальная Flash-модель, которая понимает картинки>
   ```
4. Никому не показывай ключ и не вставляй его в чаты с ИИ. Файл `.env` уже в `.gitignore`.

## Общий контекст (вставлять в начало КАЖДОГО промпта)

```
Проект Jarvis — управление ПК с телефона естественным языком (дипломная, тема
«AI-агент для автоматизации многоэтапных пользовательских задач»). Центр работы —
LLM + computer-use агент, плюс измеримая часть (точность распознавания намерений,
success rate агента).
Автор учится: объясняй код по ходу, по-русски, маленькими проверяемыми шагами,
после каждого шага — как проверить.

Архитектура (Windows 11):
  Телефон (KMP/Compose) <--WS--> Релей (Spring Boot, Java 21, Docker) <--WS--> Агент (Java 21, трей)
  C:\diplom\jarvis          — :shared (протокол Kotlin) + :androidApp (Compose, OkHttp)
  C:\diplom\jarvis-relay    — релей + PostgreSQL, docker compose (restart: unless-stopped), секреты в .env
  C:\diplom\jarvis-agent    — агент: AgentConfig (agent.properties), TokenStore (token, deviceId),
                              AgentTray, PairPhoneDialog (QR), CommandExecutor, пакет vision/

ИНВАРИАНТЫ (не ломать):
 1. Протокол WebSocket (JarvisMessage/Command) меняется синхронно в 3 местах: Kotlin :shared,
    Java релей, Java агент; JSON 1:1, дискриминатор "type". REST-эндпоинты релея — не протокол.
 2. CommandWhitelist — граница безопасности. ЛЮБАЯ команда от LLM проходит whitelist ПОСЛЕ
    разбора. shutdown/reboot вне списка.
 3. Ключ LLM ТОЛЬКО в .env релея. Не в APK, не в агенте, не в логах, не в URL (передавать
    заголовком x-goog-api-key, а не ?key=).
 4. Агент сам звонит на релей.
 5. Токены и deviceId переживают перезапуск; токены не логировать.

ТЕКУЩЕЕ СОСТОЯНИЕ:
- Всё поднимается само: релей и Postgres в Docker, агент в автозапуске с треем, телефон
  привязывается по QR (PairRequest -> phone_bindings). Команды доходят end-to-end.
- Агент аутентифицируется в REST релея заголовками X-Device-Id + X-Device-Token
  (так уже работает POST /api/agent/phone-pairing-code в AgentPairingController).
- Разбор фраз на релее: IntentParser; GeminiIntentParser (@Primary) при пустом ключе падает
  на StubIntentParser (regex: скрин/процессы/заблокир/ютуб/«открой x.y»/тише/громче/найди/лайк).
  Модель по умолчанию в application.yml — gemini-2.0-flash (СНЯТА С ПОДДЕРЖКИ, заменить).
- Команды агента: open_url, screenshot, list_processes, kill_process, lock_screen, click,
  type_text, scroll — работают; set_volume и open_app — ЗАГЛУШКИ ("TODO").
- Vision-агент написан, но НЕ проверен: vision/GeminiVisionAgent (сам ходит в Gemini с
  GEMINI_API_KEY из env агента — это НАРУШАЕТ инвариант 3, исправляем в этом шаге),
  BrowserAgent (scope=BROWSER, Selenium/DOM), ScreenAgent (scope=SCREEN, по пикселям).
  Команда agent_task(goal, scope, maxSteps) вызывает их из CommandExecutor.
```

```
[Общий контекст]

Задача: включить LLM на релее — умный разбор фраз и прокси для vision-агента, плюс журнал
для будущих замеров. Протокол WebSocket НЕ менять. По одному пункту, после каждого — проверка.

L1. Конфигурация модели.
  - JARVIS_LLM_MODEL прокинуть в docker-compose (из .env) и в .env.example; дефолт в
    application.yml заменить на актуальную Flash-модель (спроси у автора, какую он выбрал в
    AI Studio, не выдумывай название).
  - Ключ передавать заголовком x-goog-api-key, НЕ в query-строке. Никогда не логировать ключ.
  - При старте залогировать: «LLM: включена, модель X» или «LLM: ключа нет, regex-режим».

L2. GeminiIntentParser — надёжный разбор.
  - generationConfig: responseMimeType "application/json" (+ responseSchema, если удобно),
    temperature 0.
  - Промпт: список ВСЕХ команд (set_volume, open_url, open_app, screenshot, lock_screen,
    list_processes, kill_process, agent_task{goal, scope: browser|screen, maxSteps})
    + 10–15 примеров на русском, включая разговорные («сделай потише», «закрой хром»,
    «запусти блокнот», «найди на ютубе видео про котиков и открой первое» -> agent_task browser)
    + {"type":"unknown"}.
  - Таймаут 8 с; при ошибке сети/квоты/кривом JSON — fallback на StubIntentParser.
  - Ответ LLM — ТОЛЬКО предложение: результат идёт через CommandWhitelist как сейчас.
  - Обновить StubIntentParser: «закрой <имя>» -> kill_process, «запусти <программа>» -> open_app;
    порядок правил: «найди ...» проверять РАНЬШЕ «ютуб».

L3. Журнал разбора для научной части: таблица intent_log
  (id, occurred_at, device_id, phrase, parser = llm|stub, command_type, command_json,
   latency_ms, whitelisted bool, error). Писать на каждую фразу.
  GET /api/intent-log?format=csv (X-Admin-Token) — выгрузка для Excel.

L4. LLM-прокси для агента (чтобы ключ жил только на релее):
  - POST /api/agent/llm/generate, аутентификация X-Device-Id + X-Device-Token
    (переиспользовать проверку из AgentPairingController, вынести в общий сервис).
  - Тело: {"prompt": "...", "imageBase64": "..." (необязательно), "mimeType": "image/jpeg"}.
    Релей сам собирает запрос generateContent с моделью из конфига и возвращает
    {"text": "<ответ модели>"}; ошибки — 502 с понятным текстом.
  - Ограничения: тело до 6 МБ; не больше 20 запросов в минуту на агента (простой счётчик
    в памяти); таймаут 30 с. В лог — только device_id, размер, задержку, статус.
  - Каждый вызов писать в таблицу agent_llm_log (device_id, occurred_at, latency_ms, ok) —
    пригодится для замеров.

L5. Тесты: GeminiIntentParser с подменённым HTTP-ответом (корректный JSON, "unknown",
  мусор -> fallback), прокси — отказ без токена агента.

Проверка: в чате телефона «сделай потише», «закрой хром», «запусти блокнот»,
«открой википедию» -> в intent_log parser=llm и верные команды; выключить интернет ->
parser=stub, релей не падает.

```
[Общий контекст]

Задача: убрать ключ из агента (vision идёт через прокси релея), доделать заглушки,
сделать agent_task безопасным и проверяемым. Протокол WebSocket НЕ менять.

A1. Vision через релей.
  - Новый класс RelayLlmClient: POST <http-адрес релея>/api/agent/llm/generate с

  - GeminiVisionAgent переделать так, чтобы он собирал промпт/картинку как раньше, но
    отправлял через RelayLlmClient. Удалить чтение GEMINI_API_KEY и прямые вызовы Google.
    isConfigured() = агент привязан (есть токен). Интерфейс VisionAgent не ломать.

A2. open_app — вместо заглушки, СЛОВАРЬ разрешённого (не произвольный путь!):
  программы: блокнот/notepad, калькулятор/calc, проводник/explorer, paint/mspaint,
  браузер/chrome/edge (браузер по умолчанию), диспетчер задач/taskmgr;
  папки: загрузки, документы, рабочий стол, изображения (через explorer <путь>).
  Неизвестное имя -> ERROR «не знаю такую программу, могу: ...». Словарь вынести в
  отдельный класс AppCatalog — легко расширять и описать в дипломе.

A3. set_volume(level 0..100) — без сторонних утилит: через PowerShell + WScript.Shell SendKeys
  клавишами громкости (сначала 50× «тише» до нуля, затем level/2 × «громче»). Объясни
  ограничение (шаг 2%). Если найдёшь надёжный способ через Core Audio API из Java/PowerShell
  без установки программ — предложи как вариант.

A4. agent_task — безопасность и наблюдаемость:
  - Жёсткие лимиты: maxSteps (не больше 20), общий таймаут 3 мин, пауза между шагами.
  - Разрешённые действия vision-агента: click, type, scroll, navigate, done. BROWSER — только
    внутри управляемого окна Selenium. В type запрещено вводить пароли и данные карт
    (если цель/поле похоже на пароль/оплату — стоп с объяснением).
  - Защита от prompt injection: текст со страницы в промпте помечать как ДАННЫЕ, а не
    инструкции; действие должно следовать из ЦЕЛИ пользователя.
  - Пока задача идёт — трей показывает «выполняю: <цель> (шаг N)»; повторный agent_task во
    время выполнения -> ERROR «агент занят».
  - Итоговый CommandResult: OK/ERROR, message = краткий итог + число шагов + время; после
    выполнения отправить финальный ScreenFrame (скриншот результата).
  - Журнал каждого запуска в $HOME\.jarvis-agent\runs\<дата>-<id>.jsonl (цель, шаги, действия,
    задержки, итог) — это сырьё для success rate в дипломе.

A5. Проверка ScreenAgentDemo/VisionAgentDemo — оставить как ручные тесты, но через релей.

Проверка: в чате «найди на ютубе видео про котиков и открой первое» -> открывается браузер,
через несколько шагов играет видео, на телефон приходит итог и скриншот; в runs\ появился журнал.
«запусти блокнот», «открой загрузки», «сделай громкость 40» работают.

## Финальная проверка шага

| # | Фраза (текст или голос) | Ожидание |
|---|---|---|
| 1 | «сделай погромче» / «громкость 40» | громкость меняется; intent_log: parser=llm, set_volume |
| 2 | «закрой блокнот» | kill_process notepad.exe |
| 3 | «запусти калькулятор», «открой загрузки» | открываются |
| 4 | «открой википедию» | open_url https://…wikipedia.org |
| 5 | «выключи компьютер» | DENIED (whitelist), в журнале whitelisted=false |
| 6 | «найди на ютубе видео про котиков и открой первое» | видео открыто; итог + скриншот; журнал в runs\ |
| 7 | Выключить интернет → «скриншот» | parser=stub, работает |
| 8 | `GET /api/intent-log?format=csv` | открывается в Excel |

**Следующий шаг:** научная часть. Датасет из 100+ фраз на русском с правильными ответами, автоматический прогон через `/api/intent-log`, точность LLM против regex. Для агента: 20–30 задач, success rate, число шагов, задержка. Итог — таблицы и графики для главы «Экспериментальная оценка».
