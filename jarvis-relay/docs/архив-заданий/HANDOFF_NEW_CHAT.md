## Проект
Дипломная (бакалавриат). Jarvis — управление ПК с телефона по естественному языку.
Тема кафедры (Вариант A, п.8): «AI-агент для автоматизации многоэтапных пользовательских
задач». Центр — LLM + computer-use агент, а не «пульт». Научная часть (accuracy/success rate)
запланирована, но сейчас сознательно отложена — в приоритете новые функции приложения.

## Инварианты (НЕ ЛОМАТЬ)
1. Протокол (`JarvisMessage`/`Command`) меняется синхронно в 3 местах: Kotlin `:shared`,
   Java релей, Java агент. JSON 1:1, поле `"type"`. REST-эндпоинты релея (`/api/...`) —
   НЕ протокол, их можно менять свободно.
2. `CommandWhitelist` (релей) и `AppCatalog`/`FileCatalog` (агент) — границы безопасности.
   shutdown/reboot вне whitelist. Новая команда — явно добавляется в список.
3. Ключ LLM только в `.env` релея. В агенте/APK его нет — vision ходит через
   `POST /api/agent/llm/generate` на релее (`RelayLlmClient` в агенте,
   аутентификация заголовками `X-Device-Id`/`X-Device-Token`).
4. Агент сам звонит на релей. Токены/deviceId переживают перезапуск, не логировать их.

## Решения, которые уже приняты (не предлагать заново)
- Остаёмся на облачном Gemini (`gemini-2.5-flash`), не переходим на локальную модель —
  сознательный выбор 13 сен, несмотря на то что бесплатный уровень Gemini не работает в
  Казахстане (пришлось привязать карту, залито $5 — надолго хватит).
- Ноутбук: есть отдельная видеокарта NVIDIA/AMD, 16 ГБ ОЗУ (на случай, если вернёмся к
  локальной модели).
- Wake-on-LAN изучали через `powercfg`/`getmac` — работает только через Ethernet-кабель
  (Wi-Fi адаптер MediaTek его не поддерживает) и только внутри одной сети с телефоном; плату
  ESP32 для будильника решили не покупать. Реализация — чистый UDP magic packet прямо с
  телефона (без релея, т.к. релей спит вместе с ПК), MAC берётся из QR-кода привязки.
- Мультипривязка (несколько телефонов/ПК) через QR — сделана и работает.
- 13 сен (вечер): научный/eval-шаг сознательно поставлен на паузу — пользователь попросил
  сначала докрутить фичи (живой экран, Wake-on-LAN). Не предлагать eval первым.

## Текущее состояние кода (проверено чтением файлов на ПК 13 сен, не с чужих слов)
- Разбор фраз: `GeminiIntentParser` (`@Primary`) с откатом на `StubIntentParser` (regex).
  Ключ передаётся заголовком `x-goog-api-key`. Модель из `JARVIS_LLM_MODEL` в `.env`.
- Разбор пишется только в консольный `log.info` — таблицы для замера точности ещё нет
  (`intent_log`, `POST /api/eval/intents`) — часть отложенного `STEP_EVAL_AND_FEATURES_PROMPTS.md`.
- `open_app` реальный (по словарю `AppCatalog`: notepad/calc/explorer/mspaint/taskmgr, браузер
  по умолчанию, папки Downloads/Documents/Desktop/Pictures). `open_file` ещё нет — тоже в
  отложенном шаге.
- `agent_task` (vision-агент) ограничен `SensitiveInputGuard` (блокирует ввод в поля вида
  пароль/оплата), каждый запуск пишет JSONL в `$HOME\.jarvis-agent\runs\` через `RunJournal`
  (цель, шаги, длительность, трейс) — сырьё для success rate, общего отчёта по всем файлам
  сразу (`RunReport`) пока нет.
- Протокол уже содержал задел на стриминг: `ScreenFrame.seq: Int?` с комментарием «номер кадра
  при стриминге; null для разового скриншота» — но реально не использовался до текущего шага.
- **Текущий шаг (`STEP_LIVE_SCREEN_AND_WAKE_PROMPTS.md`) отправлен пользователю и записан в
  `docs\`, но на момент этого хендоффа ещё НЕ прогнан через ИИ-агентов в подпроектах** —
  проверяй фактическое состояние кода, не считай, что это уже сделано:
  - Релей: новые команды `start_screen_stream`/`stop_screen_stream` + whitelist.
  - Агент: `ScreenStreamer` (push через `Consumer<JarvisMessage>`, fps 1–5, ширина ≤960px,
    автостоп 10 мин, взаимоисключение с `agent_task`), `LanAddress.Candidate` получает `mac`,
    `PairPhoneDialog` кладёт `&mac=` в QR.
  - Приложение: `ChatViewModel` делит кадры по `seq` (null → чат, не-null → новый экран
    «Экран ПК»), новый `sendCommand(Command)`, `PairingQr`/`DeviceRepository` получают
    nullable `mac`, новый `WakeOnLan.kt` (UDP magic packet), кнопка 🔌 в `DevicesScreen`.
  - Опционально (можно пропустить): тап по экрану на телефоне → клик мышкой на ПК.
